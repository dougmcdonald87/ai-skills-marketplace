# ADR-0002: Editorial register design + UK locale

## Status
Accepted

## Context
The first deployed version of the marketplace looked generic: system fonts, a grey page, white rounded cards, a centred column. That is the default AI-product look, and every AI marketplace looks like it. The site is the entire product — there is no app, no backend and no account — so the design *is* the pitch.

Separately, the marketplace is published from Arbroath, Angus, by a UK seller. The first version priced entries in USD and used American spelling. That was wrong on every axis: the wrong currency for the buyer, the wrong currency for the seller's PayPal account, and the wrong voice.

## Decision
Adopt an **editorial catalogue** aesthetic — a letterpress-style technical register — and fix the locale to en-GB / GBP.

### Design
- Display: Fraunces (variable, optical size 144). Body: IBM Plex Sans. Technical labels, prices and entry numbers: IBM Plex Mono. All from Google Fonts.
- Warm paper ground (`#f2efe7`), warm-black ink, hairline rules, one accent: wax-seal red (`#9a1b16`).
- Entries are numbered ("No. 001") and set like catalogue entries rather than product cards.
- Each entry page carries a **specification** sheet derived entirely from the entry's own data, plus generic install steps.
- The footer is a printed **colophon** carrying the place of publication and payment terms.
- Deliberately light. The category default for AI products is dark mode with an indigo gradient; inverting that is the cheapest way to be recognisable.

### Locale
- `lang="en-GB"`, British spelling, "one-off" not "one-time".
- Prices formatted with `Intl.NumberFormat(locale, {style:'currency', currency})`. The locale and currency live in `skills.json`, so no symbol is ever hardcoded.
- Place of publication: Arbroath, Angus DD11 4AX, Scotland. Not Tayside — that is the police area, not the county.

## Rationale
- The design is the only thing a visitor judges before paying. Generic equals untrustworthy for a marketplace whose whole claim is curation.
- A catalogue register matches the product: skills are artefacts with a specification, sold one at a time, with a publisher behind each one.
- GBP is simply the correct currency for a UK seller and a mostly-UK buyer at a UK address. Pricing in USD would add a currency-conversion step to every transaction and pay PayPal more in fees.
- Putting the address in the colophon makes the place of publication part of the identity rather than a compliance afterthought.

## Consequences
### Positive
- Recognisable at a glance; not mistakable for a template.
- The location becomes a brand asset.
- No currency symbols hardcoded, so changing locale is a one-line edit.
- Web fonts and a shared stylesheet are a deliberate, documented departure from the original "system fonts, one file" standard (see CODING-STANDARDS rules 2 and 4).

### Negative
- Three font families cost three requests. Mitigated by `display=swap` and a single shared stylesheet.
- Web fonts are an external dependency, so the site needs a network connection to look right. Acceptable: the site is already served over HTTPS and the register data is fetched over the network anyway.
- The specification sheet asserts nothing that is not already in skills.json, so it must be regenerated when the data shape changes.

## Alternatives considered
- **Dark mode with an indigo gradient**: rejected. It is the category default and reads as a clone.
- **Keeping system fonts**: rejected. It was the single clearest reason the first version looked basic.
- **A full design system in a build step**: rejected. 4GB RAM, no budget, and a build step would break the "open the file and it works" property.
- **Keeping USD**: rejected. Wrong for the seller, wrong for the buyer, and needlessly expensive in PayPal fees.
