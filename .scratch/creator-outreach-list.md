# Creator outreach list — supply side for The Agent Register

Compiled 18 October 2026. All data gathered from primary sources via the authenticated GitHub API (`gh api`, `gh search repos`) plus direct fetches of the creators' own sites. No secondary blog descriptions were used as evidence.

## How to read this

Every row is a real person (a GitHub **User**, not an Organisation) who owns a public repository containing Agent Skills in the `SKILL.md` format. Each row was checked individually against the GitHub REST API: the repository exists, the licence file was read, the file tree was walked to count `SKILL.md` files, and the README was read.

**Columns.** *Name* is exactly as the person's own GitHub profile shows it. *Primary URL* is their GitHub profile or their own site. *Skill repo* is the specific repository holding the skills. *What it does* is summarised from that repository's own README. *Licence* is the licence the repository itself states — read from the licence file via the API, never inferred. *Why it fits* is one line on marketplace suitability. *Contact* is the email published on their GitHub profile, or "GitHub issue" where none is published. *Evidence* names the exact URL and the specific thing observed there.

**Licence caveat.** Skills under a non-commercial or copyleft licence cannot legally be resold in a paid marketplace without the author's permission. Those rows are kept and flagged rather than dropped, because the permission conversation is part of the pitch — but they are not straightforward listings.

**Already-listed caveat.** Almost every creator in this table is already on at least one free install directory. That is distribution, not commerce. The directories they appear on are listed in the Flags section.

**Star counts were deliberately not used** as a ranking signal. Several repositories report star totals far above anything the GitHub search API would return organically, so the counts are not trustworthy here. Suitability is judged on licence, breadth and multi-harness portability instead.

**Next step.** Contact routes: eight creators publish an email address; the rest need a GitHub issue. Roughly a third are reachable by email directly today.

## Method and caveats

- All repository data was retrieved through the authenticated GitHub API using `gh api`. No unauthenticated scraping of `api.github.com` was performed.
- Licence values come from the GitHub licence API reading the repository's own licence file. Two repositories returned SPDX `NOASSERTION` and were resolved by reading the licence file text directly: `deanpeters/Product-Manager-Skills` (CC BY-NC-SA 4.0) and `Imbad0202/academic-research-skills` (CC BY-NC 4.0).
- Skill counts are the number of paths matching `SKILL.md` in the recursive git tree. **These counts are inflated** wherever a creator ships one skill replicated across per-harness directories. `OthmanAdi/planning-with-files` reports 18 for what is effectively one skill; `pbakaus/impeccable` reports 25 for two. Where the table gives a distinct-skill figure instead, it was counted by directory name.
- Email addresses were read from the GitHub profiles' public `email` field. Four creators have a website or email in the `blog` field instead of `email` (noted in the Contact column). The remainder have neither and must be contacted by GitHub issue.
- Star counts were excluded from the ranking for the reason given in the preamble.
